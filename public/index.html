Unused Indexes source: $indexStats — 0 ops since last server start

Explanation
Creating unnecessary indexes leads to a bloated collection and slow writes. Consider each query your application performs and whether it justifies an index. Remove indexes that are unused, either because the field is not used to query the database or because the index is redundant.

Recommended Actions
1. Double check all application code to confirm the index pattern is not used in any operations.
2. Hide these unused indexes to test impact without dropping them.
3. After one full business cycle, drop the index.

Storage & Fragmentation per collection — daily scan — source: collStats

Explanation
Fragmentation mainly matters when you are disk-bound or need to shrink storage.

To allow the WiredTiger storage engine to release this empty space to the operating system, you can de-fragment your data files. This can be achieved by using the compact command or the autoCompact command (from MongoDB 8.0).

Recommended Actions
When fragmentation reaches a significant level, create a support ticket requesting a scheduled rolling resync (high availability) during a maintenance window. This is often the easiest approach on managed clusters.
